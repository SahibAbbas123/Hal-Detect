## 1. What was wrong

`archive/scripts/relational_verifier_phase3d.py:194` keys every NLI score on

    nli__{claim[:60].replace(' ', '_')}__{passage[:40].replace(' ', '_')}

On the perturbed negatives the 60-character cut lands **mid-number**. Four claims that
differ only in a dollar figure — `$700bn`, `$707bn`, `$735bn`, `$7000bn` — truncate to
the identical `...Act_of_2008_provided_$7`. The first one scored wrote a cache entry;
every later one read it back as its own. `$8` (`SYN_QUAN_029`) got its own key, which is
exactly why 029 was never contaminated.

**Contamination requires BOTH halves to match.** A shared `claim[:60]` is necessary but
not sufficient, because `passage[:40]` is in the key too. 41 rows share a claim prefix;
**26 share a full legacy key** (78 pairs). The other 15 split 8 with no surviving
passages and 7 whose keys genuinely differ.

**Scope was found by grouping the UNION of both populations.** The documented failure is
a perturbation colliding with *its original*, and the original lives in the natural
results file while the perturbation lives in the negatives file. Neither existing audit
reads both — `rq2_collision_robustness.py` reads the natural 356,
`negatives_cache_audit.py` the negatives. **The bug is invisible to each audit
separately and visible only to their union.** This is the reusable part.

## 2. The validity gate that makes the numbers attributable

Two gates, both PASS, and the second is the one that matters most.

- **prep gate.** Re-derive each row's recorded `(entail, contradict)` as MAX over the
  **legacy** keys and require equality with the recorded CSV. **26/26.**
- **apply gate (`--simulate`).** Feed the recorded scores back through the new code
  path; it must reproduce the recorded verdicts with **zero** movement. **0 of 26 on all
  three sets.**

**And the run produced a third gate that was not designed in.** Nine of the 26 rows came
back **byte-identical to four decimals** — `B3_02_C07`, `B3_02_C08`, `B3_06_C11`,
`B3_06_C12`, `Q1_C02`, `Q2_C11`, `Q5_C02`, `Q7_C04`, `SYN_QUAN_030`. If the Colab
transformers/torch build or the CPU numeric path differed from the recorded run, **all
26** would have drifted. Nine exact reproductions establish that the model path matches,
so the movement in the other 17 is attributable to the key change and not to a version
artifact. **Record this pattern: an unchanged control subset inside the treated set is a
free version check, and it is stronger than any assertion about pinned versions.**

**1 → 1**.

## 4. Two corrections this produced

### 4a. The FPR/J worry I raised is RESOLVED, in the reassuring direction

Before the run I flagged that `Q1_C02` — gold TRUE, predicted **FALSE** at
`c = 0.5008`, sharing a score with `SYN_TEMP_056/057/058` — might be a confident error
inherited from a perturbed variant, which would mean the published **J = +0.330** and the
§3 CITATION `FPR 2/24` vs L1b `0/24` comparison rested partly on an artifact.

**It does not.** `Q1_C02` is one of the nine rows that did not move: it **wrote** the
cache entry, and the five `SYN_TEMP_056–060` rows inherited from it. Its `c = 0.5008` is
a genuine BART score. **The published FPR and J are not inflated by this collision.**
State it as a closed negative result, not as an open risk.

### 4b. `CLAUDE.md`'s "five missed detections that are cache artifacts" was WRONG

The `Q5_C04` + `SYN_QUAN_033–037` group was the headline symptom: six claims with six
different values (1.1, 1.2, 1.4, 1.7, 2.2, 11.0) all carrying `e=0.6139 c=0.1117`, five
gold FALSE and all five scored TRUE. The collision **is** real and **is** now broken —
one recorded score pair became **six distinct** pairs, entail 0.5203–0.6456, contradict
0.1072–0.2245.

**But not one of the five became a detection.** Every fresh contradict lands in
0.107–0.225, nowhere near `CONTRADICT_THRESHOLD = 0.40`. **These are genuine misses, not
cache artifacts.** The collision was concealing a real non-detection, not a real
detection. `CLAUDE.md` claimed the opposite for days.

This is R8's lesson in a new place: **a known bug adjacent to a bad number is not
evidence the bug caused the bad number.** The rescore was still worth running — it is
what turned a supposition into a measurement, and it did pay off three rows away.

### 4c. `wrote` / `inherited` is per-score, not per-row

The apply script's inheritance report classifies a row by whether its max moved. That is
too coarse: a row takes a max over up to 3 passages, and different passages' entries can
have been written by different members. `Q5_C04` kept `contradict = 0.1117` **exactly**
while its entail moved 0.6139 → 0.6456 — it wrote the contradict-max passage's entry and
inherited the entail-max one. Hence the group printed `wrote=-`, which looked impossible
and is not. **Read that report as per-score, and treat a `wrote=-` group as "mixed
authorship across passages", not as "no writer exists".**

The two pairs where **neither** member moved (`B3_02_C07/C08`, `B3_06_C11/C12`) are
benign for a plainer reason: only 1 of 3 passages was shared, and it was not the
max-setter. **A collision inside a max is inert unless it lands on the argmax.**

## 5. What this does and does not do to published numbers

**Nothing published moves yet, and the reason is a denominator, not a rounding choice.**

All three new detections — `SYN_QUAN_027/028/032` — are inside the audit's 16-row
`affected` set, which is **exactly the set the strict tier excludes**. The published
baseline TPR **37/68 = 54.4%** counts the strict tier, so these rows were never in its
denominator. Fixing them changes no currently-quoted figure.

**What adoption would buy is population size, which is the thesis's binding
constraint.** `CLAUDE.md` §5: *"14 gold negatives across the natural 356 is the binding
constraint on every detection claim in the thesis."* The collision costs a further 16 of
84 synthetic negatives. Post-rescore those 16 have real, distinct scores and the reason
for excluding them is gone, so the usable population grows from **68 toward 84** — about
**+24%** — which tightens every CI on the negatives side.

**Do not compute the new TPR by hand.** The tier logic in
`current/negatives_cache_audit.py` is four tiers with `fabricated`/`partial`/`duplicate`
classes and a keep-the-first rule, not a subtraction. Adoption needs:

1. a **new** negatives results CSV carrying the rescored values for these 17 rows —
   `current/nonrouted_negatives_results.csv` is a quoted baseline and was **not**
   rewritten (R19);
2. `negatives_cache_audit.py` re-run against it, with its `DROPPED` / collision-tier
   logic revisited, since the condition it filters on no longer holds;
3. the §3 per-type J table re-derived by **running the script**, never by editing cells.

**This is an author decision, not a mechanical follow-through** — it changes a published
denominator, and R1b applies with force: after adoption, "68" and "84" both name real
sets and quoting either without saying which set it counts is the exact hazard that rule
exists for.
