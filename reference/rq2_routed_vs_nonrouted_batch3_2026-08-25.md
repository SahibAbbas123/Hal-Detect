## 3. What this actually shows — five findings, three of them uncomfortable

### 3.1 Nothing here separates routed from non-routed. Every CI overlaps.

| type | routed | baseline 3d | verdict |
|---|---|---|---|
| RELATIONAL | 81% [62, 91] n=26 | 68% [53, 81] n=38 | **overlap** |
| QUANTITATIVE | 100% [68, 100] n=8 | 73% [52, 87] n=22 | **overlap** |
| CITATION | 80% [49, 94] n=10 | 50% [15, 85] n=4 | **overlap** |
| ENTITY_ATTRIBUTE | covers 0/22 | 86.7% | no accuracy exists |
| TEMPORAL | covers 0/12 | 54.5% | no accuracy exists |

**This is the honest headline.** Not "routing wins", not "routing loses" — *this
experiment, on this claim set, cannot tell.* Effective n per type after coverage
is 8–26. That is the same trap `report-metrics-honestly` documents for the
original 80.77%, arriving again one level up.

### 3.2 Routed loses the coverage–accuracy tradeoff to the baseline's better setting

Pooled routed is **36.1% cov / 84.1% acc**. Baseline 3e is **51.6% / 82.5%** —
**+15.5pp coverage for −1.6pp accuracy**, and that 1.6pp is far inside the
overlap above. On the tradeoff curve the project itself chose to report,
non-routed 3e sits above routed.

Note this is *not* the strawman: 3e is the same code path, and the threshold sweep
already established that the shipped 0.50/0.40 point is dominated. A reviewer
tuning the baseline properly makes this gap wider, not narrower.

### 3.3 Routed's FALSE precision is 0.000, and the "better error profile" defence does not hold here

CLAUDE.md's stated RQ2 defence is *"the defence is the error profile, not
fairness: the baseline is wrong 90% of the time it says FALSE, whereas post-QID-fix
TEMPORAL/EA produce zero confident-wrong verdicts."*

On Batch 3 the routed **system** makes 3 FALSE calls and **all 3 are wrong**:

| claim | routed | gold |
|---|---|---|
| `B3_08_C06` The collapse of the Aral Sea killed most endemic fish species. | FALSE | TRUE |
| `B3_09_C04` Market income inequality grew due to the decline of manufacturing jobs. | FALSE | TRUE |
| `B3_11_C09` India increases its launch count through ISRO's commercial satellite programme. | FALSE | TRUE |

All three are RELATIONAL false alarms. And RELATIONAL **missed** the single gold
negative in its own slice (`B3_10_C17`, liver→glycogen, which 3d also called
confidently TRUE).

TEMPORAL/EA do produce zero confident-wrong verdicts — because they produce **zero
verdicts**. That is true but vacuous, and it cannot be quoted as an error-profile
win. At 0/3 vs 1/26 neither system has demonstrated detection; the difference is
noise. The defence needs re-grounding on the pooled set or dropped.

### 3.4 The one hallucination anyone caught was caught by the BASELINE, on a claim the routed verifier abstains on by design

`B3_02_C09` — *"Total global renewable capacity reached 3,372 gigawatts by the end
of 2023."* Gold FALSE. Baseline 3d and 3e both call it **FALSE, correctly**
(entail 0.339 / contradict 0.517). The routed QUANTITATIVE verifier **abstains** —
it is one of the five gold-FALSE QUANTITATIVE claims CLAUDE.md already identifies
as Wikidata-unreachable (IRENA renewable capacity).

This is the single most quotable counter-example in the data: **generic
Wikipedia+NLI caught a hallucination that the purpose-built verifier could not
reach.** It is also precisely what the 2026-08-23 revision predicted — those
derived-rate aggregates need a statistical-agency backend (World Bank / WHO GHO),
not Wikidata. Until QUANTITATIVE tier 2 exists, this claim is an argument *for*
the fall-through and *against* routing-as-currently-built.

### 3.5 TEMPORAL and EA cannot contribute detection evidence at any coverage

Both have **zero gold negatives** in Batch 3 (12/0/0 and 22/0/0). That is 34
claims — 28% of the slice — where F1(FALSE) and MCC are 0.000 *by construction*,
exactly as `metrics.py` warns. Fixing their coverage would raise coverage numbers
and change nothing about detection. **Coverage is not the binding constraint on
RQ2; gold negatives are.**

## 4. A file-provenance conflict that must be resolved before Chapter 4

Five files on disk give five different TEMPORAL/EA coverage figures for the same
34 Batch-3 claims:

| file | TEMPORAL | EA | status |
|---|---|---|---|
| `temporal_b3_verified_results.csv` | 1/12 = 8.3% | 0/22 | pre-QID-fix; the 1 covered claim is a **FALSE** |
| `entity_attribute_b3_verified_results.csv` | 0/12 | 1/22 = 4.5% | pre-QID-fix; the 1 covered claim is a **FALSE** |
| `temporal_b3_verified_results_phase2.csv` | **0/12** | 0/22 | post-fix — CLAUDE.md names this as "Results:" |
| `entity_attribute_b3_verified_results_phase4.csv` | 0/12 | **0/22** | post-fix — CLAUDE.md names this as "Results:" |
| `temporal_ea_hybrid_b3.csv` | 11/12 = 91.7% | 17/22 = 77.3% | hybrid fall-through, **unreviewed** |
| `temporal_ea_results.csv` | 4/13 | 21/45 | 58 rows — **not Batch 3** |

**CLAUDE.md's summary table claims post-fix TEMPORAL 1/12 = 8.3% and EA 5/22 =
22.7%. No file on disk yields EA 5/22.** The 8.3% comes from the *pre*-fix file,
whose single covered claim is the confident-wrong FALSE the QID fix was written to
eliminate.

CLAUDE.md **contradicts itself** here. Its QID-fix section says coverage moved
*8.3% → 0%* "because the only 'covered' claims had been the wrong ones", and names
phase2/phase4 as the results. That agrees with the files. **The summary table row
is the error.**

**Author decision:** either correct that row to 0%/0%, or locate and commit the
run that produced EA 5/22. Nothing downstream can be trusted until one of those
happens, because that row is what makes TEMPORAL/EA look partially functional.

### The hybrid file is not a rescue

`--variant hybrid` lifts pooled routed coverage to **59.0% / 81.9%**, which would
beat 3e on the tradeoff. But its FALSE predictions go 3 → 9 and **all 9 are
wrong** (precision still 0.000, MCC −0.052). That is the project's signature
regression — coverage up, precision down — for the third time.

It also contradicts `hybrid_fallthrough.py --diagnose`, which was run and returned
**34/34 ABSTAIN**. So `temporal_ea_hybrid_b3.csv` came from some other, unrecorded
run and **must not be quoted** until its provenance is established.

## 5. What this makes the next experiment

**Batch 3 is the wrong evaluation set for RQ2.** 4 gold negatives cannot support a
detection claim. The pooled 356 has 13 — still few, but three times as many, and
the baseline is *already run on all 356*.

The asymmetry is the whole problem: **the routed verifiers have only ever been run
on Batch 3.** The one exception is CITATION — `citation_l1_results.csv` already
spans all three sets (11 b1 + 6 p2 + 12 b3 = 29, all present in the baseline), so
CITATION alone could be compared on 29 claims today at no cost.

So, in order:

1. **Free, no run:** extend the CITATION comparison to its full 29 rows.
2. **Needs a run (author authorisation):** RELATIONAL / QUANTITATIVE / TEMPORAL /
   EA on Batch 1 + Phase 2 — 234 more claims. This is what turns RQ2 from a null
   result into a measurement. Report with and without Phase 2, per the label rule.
3. **Independent of both:** the 27 synthetic negatives
   (`relational_negatives_batch3_merged.csv`) are the only place a detection number
   can come from at present, and they are **not** in the baseline's 356 — so the
   baseline has never been scored on them. Doing that is also free-ish and is the
   fastest route to a real F1(FALSE) comparison.

Item 3 is probably the highest-value next step: it is the only one that attacks
the binding constraint (gold negatives) rather than the non-binding one (coverage).
